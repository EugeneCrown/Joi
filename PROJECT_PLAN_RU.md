# План проекта: ИИ‑ассистент для M5Stack Tab5

## Общее описание
В этом репозитории находится ядро AI‑ассистента, работающего на **M5Stack Tab5**. Ассистент построен на базе фреймворка **Joi** и будет предоставлять голосовое взаимодействие, локальную память и выполнение команд для IoT‑устройств.

Ниже представлена формальная дорожная карта, разбитая на конкретные этапы и задачи, а также лёгкая система отслеживания статуса, хранящаяся внутри репозитория. План можно обновлять по мере продвижения.

---

## Цели
| Цель | Описание |
|------|----------|
| **Голосовой интерфейс** | Реализовать обнаружение wake‑word, распознавание речи и синтез речи на Tab5. |
| **Локальная модель LLM** | Запустить компактную модель (например, TinyLlama, Llama‑Cpp) на устройстве или передать её на ближайший edge‑сервер. |
| **Маршрутизация IoT‑команд** | Анализировать намерения пользователя и отправлять команды подключённым периферийным модулям (GPIO, BLE, Wi‑Fi). |
| **Память и вывод** | Хранить краткосрочный контекст и долгосрочные факты; выполнять их суммирование и поиск. |
| **Безопасность и расширяемость** | Предоставить иерархию подсказок (system, safety, routing, memory) и возможность добавления пользовательских подсказок. |

## Детализация задач (по этапам)
### M1 – Подготовка проекта
- [ ] Проверить toolchain для ESP32‑C6 (Arduino‑CLI / PlatformIO).
- [ ] Настроить CI, собирающий прошивку (`make`‑target) и выполняющий линт.
- [ ] Добавить начальные разделы в `README` (уже есть).
- [ ] Создать файл `PROJECT_PLAN_RU.md` (это вы).

### M2 – Голосовой конвейер
- [ ] Интегрировать библиотеку **Wake Word** (например, Porcupine).
- [ ] Добавить драйвер микрофона для Tab5.
- [ ] Подключить STT (например, Whisper.cpp) либо заглушку к облачному API.
- [ ] Установить и настроить бесплатный движок транскрибации whisper.cpp и его зависимости.
- [ ] Добавить TTS (ESP‑Speech, PicoTTS и др.).
- [ ] Реализовать простой state‑machine `listen → process → speak`.

### M3 – Архитектура подсказок
- [ ] Загрузка подсказок из `config/prompts/**` при старте сервера.
- [ ] Реализовать логику маршрутизации к нужной подсказке (system, safety, intent, memory).
- [ ] Написать unit‑тесты для выбора подсказки.

### M4 – Модуль IoT‑команд
- [ ] Определить JSON‑схему команд, например `{"action":"toggle_led","pin":2}`.
- [ ] Реализовать диспетчер, сопоставляющий намерения с аппаратными вызовами.
- [ ] Добавить обнаружение BLE / Wi‑Fi для внешних контроллеров.
- [ ] Написать интеграционные тесты с мок‑устройством.

### M5 – Интеграция edge‑LLM
- [ ] Оценить возможный размер модели для ESP32‑C6.
- [ ] Поскольку запуск модели на устройстве невозможен, использовать облачную LLM через API (proxyapi.ru) и обеспечить лёгкую интеграцию по REST‑API.
- [ ] Потоковая передача ответов в UI Tab5.

### M6 – Слой безопасности и тестирование
- [ ] Сформировать safety‑подсказки (`config/prompts/system/safety.txt`).
- [ ] Принудительно применять защиту от инъекций подсказок.
- [ ] Добавить CI‑тест‑сьют (pytest, cargo и пр.) с покрытием >80 %.
- [ ] Провести ручной аудит безопасности.

### M7 – Документация и релиз
- [ ] Обновить `docs/`: схемы питания, руководство по развёртыванию, обзор архитектуры.
- [ ] Подготовить релиз‑артефакты (binary прошивки, docker‑compose для edge‑сервера).
- [ ] Тегировать версию `v0.1.0`.
